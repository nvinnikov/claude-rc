# claude-rc — приложение в меню-баре

Дата: 2026-08-18
Статус: дизайн утверждён, план не написан

Часть 2 из 3. Опирается на часть 1 (`docs/superpowers/specs/2026-08-18-cli-and-resume-design.md`),
которая дала команду `claude-rc`. Часть 3 — доставка: `make install`, GitHub Release,
Homebrew tap.

## Задача

Бот сейчас живёт как процесс, который человек однажды запустил руками в терминале.
Это видно по факту: на машине он крутился девятнадцать дней с `PPID 1` — терминал,
из которого его стартовали, давно закрыт, launchd им не управляет, и первая же
перезагрузка машины оставила бы человека без бота молча.

Нужен видимый переключатель: иконка в меню-баре, по которой сразу понятно, жив бот
или нет, и клик, который его поднимает и гасит. Автозапуск при входе — чтобы после
перезагрузки не вспоминать, что бот вообще существует.

Телеграм-бот остаётся пультом с телефона. Приложение — это то, что не даёт пульту
умереть.

## Решения и их обоснование

| Решение | Выбор | Почему |
|---|---|---|
| Язык приложения | Swift, AppKit | Нативный менюбар без тяжёлого рантайма. Бандл выходит около двух мегабайт против пятидесяти у варианта с вложенным Python. |
| Связь с ядром | Запуск `claude-rc bot` дочерним процессом | Одна копия логики на CLI и приложение. IPC не нужен: состояние «жив» — это `Process.isRunning`, а не догадка по сокету. |
| Сборка | Swift Package Manager, бандл собирается скриптом | На машине стоят только Command Line Tools, полного Xcode нет. `.xcodeproj` в git не кладём: он не читается в диффе и не нужен. |
| Кто владеет процессом бота | Приложение | Выбор человека при обсуждении. Закрыл приложение — бот умер, и иконка это честно показывает. launchd-плист уходит. |
| Автозапуск | `SMAppService.mainApp`, запасной вариант — LaunchAgent | Штатный способ macOS 13+. Он требует подписи, а у нас ad-hoc — поэтому запасной путь обязателен, а не «на всякий случай». |
| Лог | `~/.claude-rc/claude-rc.log`, дозапись | Путь уже обещан `paths.log_file()` в части 1. Дозапись, а не перезапись: причина падения не должна теряться при перезапуске. |
| Иконка | SF Symbol в режиме template | Сама подстраивается под светлое и тёмное меню-бар, не требует ассетов в репозитории. |

## Архитектура

```
    ┌──────────────────────────────────────┐
    │  ClaudeRC.app (LSUIElement)          │
    │                                      │
    │  AppDelegate ── NSStatusItem, меню   │
    │       │                              │
    │       ├── CLILocator ── где claude-rc│
    │       ├── BotSupervisor ── Process   │──▶ claude-rc bot ──▶ tmux
    │       └── LoginItem ── SMAppService  │
    └──────────────────────────────────────┘
```

Четыре типа, каждый со своей ответственностью. `AppDelegate` не знает, как искать
бинарь и как считать паузы перезапуска; `BotSupervisor` ничего не знает про меню.

### `CLILocator`

```swift
enum CLILocator {
    static func find(searchPaths: [String], environmentPath: String?) -> URL?
    static func childEnvironment(base: [String: String]) -> [String: String]
}
```

Ищет `claude-rc` в `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, затем в
каталогах из `PATH`. Первое совпадение, которое существует и исполняемо.

`childEnvironment` собирает окружение для дочернего процесса. Это не украшение:
приложение, запущенное из Dock или автозапуска, получает голый `PATH`, и бот не
найдёт ни `tmux`, ни `claude`. Ровно на эти грабли уже наступали в launchd-плисте
части 1 — там `PATH` прописан руками. Приложение подставляет тот же список явно.

Обе функции чистые и принимают окружение аргументом — чтобы их можно было
проверить тестом, а не только глазами.

### `BotSupervisor`

```swift
enum BotState { case stopped, starting, running(since: Date), crashed(reason: String) }

final class BotSupervisor {
    var onStateChange: ((BotState) -> Void)?
    var state: BotState { get }
    func start()
    func stop()
    func foreignBotIsRunning() -> Bool
}
```

Запускает `claude-rc bot`, перенаправляя вывод дозаписью в `~/.claude-rc/claude-rc.log`.

**Внезапная смерть.** Процесс умер не по команде `stop` — состояние уходит в
`crashed`, и супервизор перезапускает бота с паузами 2, 5 и 15 секунд. После третьей
неудачи перестаёт пытаться и оставляет `crashed` с причиной. Бесконечная прокрутка
падающего бота — это тот же молчаливый сбой: иконка мигает, человек не понимает,
почему бот «то есть, то нет».

**Чужой бот.** Перед запуском супервизор проверяет, не крутится ли `claude-rc bot`
или `python -m clauderc.bot` вне приложения. Два поллера одного токена получают от
Telegram конфликт, и оба работают через раз. Найдя чужой процесс, приложение не
запускает свой, а показывает это в меню отдельным пунктом с его pid. Гасить чужой
процесс за человека мы не будем: мы не знаем, зачем он его запустил.

Расчёт пауз выносится в чистую функцию `backoffDelay(attempt:)` — она тестируема,
в отличие от самого `Process`.

### `AppDelegate` и меню

`LSUIElement = true`: иконки в Dock нет, окон нет.

```
◉ / ○  ← залитый символ = бот жив, контурный = нет
──────────────────────
Bot: running · 4m          ← или stopped / starting / crashed: <причина>
Stop bot                    ← или Start bot
──────────────────────
Open log
Reveal config
──────────────────────
✓ Launch at login
Quit
```

Пункт статуса неактивен, он только показывает. Заголовок пересобирается в
`menuNeedsUpdate`, а не по таймеру: пока меню закрыто, обновлять нечего.

`Reveal config` открывает в Finder тот файл, который реально использует CLI. Путь
берётся не из константы, а из `claude-rc doctor --json`: иначе приложение и тулза
разойдутся в понимании того, где лежит конфиг, и человек будет править не тот файл.

`Quit` гасит бота вместе с приложением — это прямое следствие выбранной модели
владения, и в подтверждении не нуждается: иконка всё время честно показывала,
что бот живёт внутри приложения.

### Автозапуск

`SMAppService.mainApp.register()`. Метод требует подписанного бандла; ad-hoc подписи
может не хватить. Поэтому:

1. пробуем `register()`;
2. на ошибке пишем LaunchAgent-плист в `~/Library/LaunchAgents/com.nvinnikov.claude-rc-app.plist`,
   указывающий на бандл, и грузим его через `launchctl bootstrap`;
3. в меню галочка отражает фактическое состояние, каким бы путём оно ни было достигнуто.

Запасной путь — не подстраховка «на всякий случай», а ожидаемая ветка: без
Developer ID первый вариант с большой вероятностью откажет.

### Сборка бандла

`app/Package.swift` — исполняемый продукт `ClaudeRCMenu` и тестовая цель.
`app/make-app.sh` собирает `ClaudeRC.app`:

```
ClaudeRC.app/Contents/
  Info.plist        ← LSUIElement, CFBundleIdentifier, версия из pyproject.toml
  MacOS/ClaudeRCMenu
```

Версия читается из `pyproject.toml`, чтобы приложение и тулза не разъезжались.
Подпись — `codesign --force --sign -` (ad-hoc). В `Makefile` появляется цель `app`.

## Ошибки

| Ситуация | Поведение |
|---|---|
| `claude-rc` не найден | Меню показывает «CLI not found» и команду установки; пункт запуска неактивен |
| Бот уже крутится вне приложения | Меню показывает pid чужого процесса; свой не запускается |
| Бот упал | Три перезапуска с паузами 2/5/15 с, затем состояние `crashed` с причиной |
| Лог не пишется | Приложение продолжает работать, вывод бота теряется, в меню — пометка |
| `SMAppService` отказал | Молча уходим на LaunchAgent; галочка показывает фактическое состояние |
| Конфига нет | `Reveal config` открывает каталог `~/.config/claude-rc`, а не несуществующий файл |

## Тестирование

Swift-тесты в `app/Tests/` покрывают то, что не требует GUI:

- `CLILocator.find` — порядок поиска, пропуск несуществующих и неисполняемых путей,
  разбор `PATH`;
- `CLILocator.childEnvironment` — обязательные каталоги присутствуют даже при пустом
  входном `PATH` (регрессия на те самые грабли из launchd);
- `backoffDelay(attempt:)` — 2, 5, 15 и отказ после третьей попытки;
- разбор вывода `claude-rc doctor --json`.

`BotSupervisor` целиком и меню тестами не покрываются: первый требует настоящего
процесса, второе — GUI. Проверяются руками по чек-листу в плане.

## Риски

**`SMAppService` с ad-hoc подписью.** Проверяется на первой же сборке. Если откажет —
работает запасной LaunchAgent, объём задачи не меняется. Если откажут оба, автозапуск
придётся делать инструкцией в README, и пункт меню уйдёт.

**Command Line Tools вместо полного Xcode.** Компиляция AppKit и ServiceManagement
проверена: `swiftc` собирает оба фреймворка. Не проверено, соберётся ли полноценный
бандл — это первое, что делает план.

## Вне объёма

- Управление сессиями из меню. Человек выбрал тумблер бота, а не список сессий;
  добавлять его «раз уж мы здесь» — не наше решение.
- Доставка: `make install`, Release, Homebrew tap — часть 3.
- Уведомления macOS о падении бота. Иконка и меню уже показывают состояние;
  запрос прав на уведомления ради этого не оправдан.
