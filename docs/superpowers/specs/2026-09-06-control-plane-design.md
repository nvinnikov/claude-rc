# Пульт для сессий: паспорт, состояние, действия и `--host`

Дата: 2026-09-06

Заменяет блоки 1 и 2 спеки `2026-09-04-connect-and-umbrella-design.md` (`connect`,
`--host`): они входят сюда с уточнениями. Блоки 3 и 4 той спеки (зонтики) не затронуты.

## Зачем

Сессия claude-rc живёт в tmux на одной машине, а нужна с четырёх мест:

| Кто | Вход сейчас | Что не так |
|---|---|---|
| человек с телефона | бот → каталог → ссылка → приложение Claude | работает |
| человек в терминале другой машины | `ssh host` + `tmux attach` руками | команду никто не даёт, имя сессии надо искать |
| **агент-стюард** — сессия Claude на другой (или той же) машине, через которую человек управляет остальными | придумывает `ssh … tmux capture-pane` сам | нет источника правды: имена меняются, состояния не видно, команду скинуть некуда, MCP отваливаются, порты пробрасывать вслепую |
| агент внутри RC-сессии | `claude-rc whoami` (незакоммиченный хвост) | работает |

Стюард — главный потребитель того, что здесь проектируется. Он уже делает всё, что
описано ниже (открыть сессию, посмотреть, ответить на диалог прав, перезапустить,
починить MCP, пробросить порт), но каждую команду изобретает заново. Продукт должен
дать ему по одной команде на действие и `--json` на каждую.

Вторая боль — имя. В приложении Claude сессия зовётся `city-manager-admin-wt-20260905-162321`:
слаг каталога worktree плюс ветка, сгенерированная по времени. Читать это нельзя.

## Принципы

1. **Одна машина — полный продукт, удалённость — надстройка.** Без единого нового ключа
   в конфиге всё работает на одной машине: бот, CLI, стюард в соседней сессии, агент
   внутри сессии. Ролей «управляющий» и «исполнитель» в продукте нет: любая машина с
   `claude-rc` может звать любую другую через `--host`, главной нет.
2. **Одна библиотека действий, три поверхности.** Всё новое живёт в модулях `clauderc/`.
   Бот, локальный CLI и CLI с `--host` только показывают и зовут. Хендлер бота не
   содержит механики.
3. **Стюард — не сущность продукта.** Это любая сессия Claude, которой доступен
   `claude-rc`. Ему даются команды с `--json`, а не отдельный режим.
4. **Состояние — это то, что видно на панели.** У tmux нет событий, у claude нет API
   статуса. Всё, что выводится из панели, помечено как наблюдение, и рядом всегда лежит
   сырой хвост панели.
5. **Два бота остаются.** Единый бот на парк машин не строится. Демон, свой протокол и
   гейт на отдельные вызовы инструментов — тоже нет (последнее делает приложение
   Claude; стюард при нужде отвечает на диалог через `send`, как через клавиатуру).

## Адрес сессии

На всех поверхностях сессия зовётся `repo@name`: `name` — то, что человек ввёл при
старте, иначе ветка. Ярлык хранится в user-опции tmux `@rc_label` (незакоммиченный
хвост) и уходит в `--remote-control <label>` и `-n <label>`.

Цель для любой команды — ярлык, каталог или `session_…`; разрешение через
`remote.resolve`, неоднозначность (два клона одного репозитория) даёт список и код 2,
как сейчас у `stop`.

## Паспорт

Новый модуль `clauderc/passport.py`. Структура `Passport` собирается из `RemoteSession`,
git и конфига; одна функция рендерит её в HTML для бота, текст для CLI и JSON.

| Поле | Откуда |
|---|---|
| `label` | `@rc_label`, у сессий прежней версии — имя каталога |
| `host` | конфиг `host`, пусто если не задан |
| `cwd`, `branch` | tmux, git |
| `url`, `session_id` | `@rc_url`, имя tmux после переименования |
| `mode` | `@rc_mode` (см. «Действия») |
| `state`, `listening`, `last_lines` | `state_probe` (см. «Состояние») |
| `attach` | без `host`: `tmux attach -d -t =<id>`; с `host`: `ssh <host> -t 'tmux attach -d -t =<id>'` |
| `cli` | префикс для стюарда: `claude-rc` или `claude-rc --host <host>` |

Вид в боте и в `sessions`:

```
✅ oms@mcp-fix · 2h · m1
/Users/n/services/oms-wt-mcp-fix
🌿 mcp-fix · чисто · auto
⏳ ждёт ответа · порты 3000, 5173
🔗 https://claude.ai/code/session_01SWSU…
🖥 ssh m1 -t 'tmux attach -d -t =session_01SWSU…'
🤖 claude-rc --host m1 send oms@mcp-fix '/mcp' --tail
```

`sessions --json` отдаёт список паспортов разом — один вызов для стюарда. Поля
`mode`, `state`, `listening`, `last_lines` появляются шагами 3–4 (см. «Порядок работ»);
до этого их в паспорте нет вовсе, а не пусто.

### Конфиг

Новый ключ `host = "m1"` — как эта машина зовётся по ssh с других машин. Опционален.
Без него паспорт печатает локальные формы. Добавляется в `_EXTRA_KEYS`, иначе визард
его сотрёт. В `config.example.toml` — с комментарием, что нужен только при второй
машине.

## Имя при старте и `rename`

**Старт.** В боте после выбора каталога или ветки — шаг «имя сессии»: текстовое
сообщение или кнопка «Skip». В CLI — `start --name mcp-fix`. Имя идёт в три места:
ярлык `repo@mcp-fix`, `-n`, и если сессия поднимается в новом worktree без явной
`--branch`, ветка становится `wt/mcp-fix` вместо `wt/<дата>`. Слаг — тот же
`worktrees.slug`. Пропущено — как сейчас: ветка по дате, ярлык `repo@branch`.

**`rename <target> <name>`** — команда CLI и кнопка в карточке. Меняет `@rc_label` и
шлёт в панель `/rename <name>`, чтобы приложение Claude переименовало сессию у себя.
Если у текущего claude команды `/rename` нет (проверяется по хвосту панели: ответ
«Unknown command»), ярлык всё равно меняется в tmux, а CLI печатает, что приложение
имя не подхватило. Ветка и каталог не трогаются.

Ожидание текста в боте (имя при старте, `rename`) хранится в `state.py` рядом с
текущим каталогом: переживает рестарт бота; следующее сообщение-команда ожидание
сбрасывает, чтобы не проглотить чужой текст.

## Состояние

Модуль `clauderc/state_probe.py`, функция `probe(tmux_name) -> SessionState` поверх
одного `capture-pane`:

| Состояние | Признак на панели |
|---|---|
| `working` | строка-спиннер claude (`✻ …ing…`, `… for Ns`) без рамки ввода ниже |
| `idle` | внизу пустая рамка ввода `❯` |
| `needs_input` | нумерованный диалог, `(y/n)`, `Do you want to…`, диалог доверия |
| `dead` | сессии нет в tmux |
| `unknown` | ни один шаблон не подошёл |

Шаблоны лежат в одном месте; на каждое состояние — тест с реальным снимком панели.
Сломанный обновлением claude шаблон даёт `unknown`, а не ложный `idle`.

`last_lines` — хвост панели (по умолчанию 5 строк) как есть.

**MCP.** Отдельного статуса нет: claude не даёт спросить его снаружи, а парсить вывод
`/mcp` — второй раз завязаться на разметку TUI. Действие `mcp` = `send '/mcp' --tail`.

**Порты.** `listening` — TCP-порты, которые слушают процессы панели: `pane_pid` из
tmux → потомки через `pgrep -P` рекурсивно → `lsof -a -p <pids> -iTCP -sTCP:LISTEN -P -n`.
Детерминировано. Это вход для `forward`.

**Цена.** Один `capture-pane` и один `lsof` на сессию при показе. `Watcher` состояние
не опрашивает — он по-прежнему следит только за смертью.

## Действия

Все — в новом `clauderc/actions.py`, а не в `remote.py`: тот и так держит запуск,
ссылку и гашение. Тесты — на заглушке `remote._run`.

**`send <target> <text> [--no-enter] [--tail N]`.** `tmux send-keys -l -t =<имя>:`
строкой, затем `Enter` (без него при `--no-enter`, для ответа одной клавишей на
диалог). `--tail N` ждёт 3 секунды и печатает хвост. Текст уходит в `send-keys` как
аргумент, не через shell, квотинг не нужен; `-l` защищает от трактовки как имени клавиши.

**`restart <target> [--mode M]`.** Гасит через `Watcher.kill(tmux_name, cwd)` (мимо него
нельзя, иначе карточка «сессия упала»), поднимает в том же каталоге с тем же ярлыком и
`--resume <session_id>`. Режим — из флага, иначе прежний. Прежний хранится в user-опции
tmux `@rc_mode`, которую `launch` ставит рядом с `@rc_label`. Ссылка после перезапуска
новая, паспорт обновляется. В боте кнопка «🔓 Bypass» = `restart --mode bypassPermissions`.
Если `session_id` неизвестен (сессия умерла до ссылки) — `restart` поднимает без
`--resume` и говорит об этом.

**Режим при старте.** По умолчанию `auto`; конфиг `permission_mode` переопределяет. В боте
рядом с «▶️ Start Claude RC» — «🔓 Start (bypass)». В CLI флаг `--mode` уже есть.

**`rename`** — выше.

**`connect [target] [--read-only]`** — по спеке 4 сентября, блок 1, без изменений:
`os.execvp("tmux", attach_argv(..., detach_others=True))`, без tty — код 2 с подсказкой
про `ssh -t`, `--read-only` даёт `-r`. Флаги `--start`, `--branch`, `--url`, `--cc` из
той спеки — тоже как там.

**`forward <target> [port…] [--stop]`.** Без портов берёт `listening`. Запускает
`ssh -N -L p:localhost:p <host>` на каждый порт фоново, pid — в
`~/.claude-rc/forwards/<host>-<port>.pid`; `--stop` снимает. Исполняется на клиентской
стороне и **не** проксируется: `--host` задаёт, куда идёт туннель. Без `--host` —
код 2 с объяснением, что на одной машине пробрасывать нечего. Порт, уже занятый
локально, — ошибка с текстом, не молчаливый провал ssh.

**`stop`** — без изменений.

## Флаг `--host`

Блок 2 спеки 4 сентября с уточнениями.

`claude-rc --host m1 <args>` → `os.execvp("ssh", ["ssh", "-t"|"-T", "m1", "claude-rc",
*[shlex.quote(a) for a in args]])`. `-t` для `connect`, `start`, `setup`; `-T` остальным.
Хост: `--host` > `CLAUDE_RC_HOST` > ничего (нет — работаем здесь). Ключа «хост по
умолчанию» в конфиге нет: у стюарда хост в каждой команде явно, а такой ключ снова
протаскивает роль «управляющий».

**Конфиг на клиенте не читается.** Всё нужное есть в аргументах; ридер без токена из
старой спеки не нужен. Только `forward` читает локальный `~/.claude-rc/forwards/`.

**Не проксируются:** `bot`, `forward`, `update` — код 2 с объяснением. `update` — потому
что оно гасит приложение на той машине и должно идти из её Терминала. Относительный
путь при `--host` — код 2.

**Сервер о клиенте не знает.** Команда приходит как локальный `claude-rc`. Без
рукопожатия и версий протокола: разошлись версии — стюард видит ошибку argparse.

**`whoami` не для стюарда.** Он не в RC-сессии; ему `sessions --json`. README говорит
это прямо, иначе агент первым пробует `whoami`.

## Бот

Меняются карточки и кнопки, механики в хендлерах не прибавляется.

- карточка сессии = паспорт в HTML; ряд кнопок: `Open in Claude` · `⏹ Stop` · `🔓 Bypass`
  · `🔌 /mcp` · `✏️ Rename` · `📋 Tail`;
- `Tail` — хвост панели в `<pre>`; `/mcp` — `send` и хвост через 3 секунды;
- шаг «имя сессии» при старте с кнопкой `Skip`; «🔓 Start (bypass)» рядом с запуском;
- `callback_data` — токены из словаря, как сейчас; ожидание текста — в `state.py`;
- всё под `allowed_user_id`.

## Порядок работ

Каждый шаг — отдельный коммит, гейт зелёный.

0. Закоммитить хвост: `whoami`, `@rc_label` (`make check`, затем коммит).
1. `host` в конфиге и `_EXTRA_KEYS`; `passport.py`; `sessions`/`sessions --json`/карточка
   бота через паспорт; `start --name`, шаг имени в боте, ветка `wt/<slug>`; `rename`.
2. `--host`.
3. `state_probe`: состояния, хвост, порты — в паспорт.
4. `@rc_mode`, `auto` по умолчанию, `send`, `restart --mode`, кнопки `Bypass`/`/mcp`/`Tail`,
   `Start (bypass)`.
5. `connect`, `forward`.
6. README (обе версии): абзац «одна машина — полный продукт, `host` при второй»;
   раздел для стюарда с `sessions --json` и командами; «Грабли» и «Design notes».

После шага 2 стюард уже работает через CLI, поэтому `--host` идёт раньше состояния.

## Грабли, которые видны заранее

- **`send-keys` без `-l`** трактует `Enter`, `Up`, `C-c` как клавиши: текст пользователя
  уходит с `-l`, клавиши — отдельным вызовом.
- **`restart` без `Watcher`** даёт карточку «сессия упала» вслед за собственным нажатием.
- **Имя tmux меняется под ногами**: `restart` держит `cwd` и `session_id`, а не имя.
- **Шаблоны состояния завязаны на TUI.** Каждый — с тестом на снимке; неизвестное —
  `unknown`, а не догадка.
- **`forward` на клиенте, всё остальное на сервере.** Единственное исключение из правила
  «`--host` = выполни там»; в README это оговаривается отдельно.
- **`_EXTRA_KEYS`** для `host`, иначе `setup` его сотрёт.
