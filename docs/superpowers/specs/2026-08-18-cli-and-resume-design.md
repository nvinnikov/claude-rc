## Задача

Сегодня проект — репозиторий, который запускают из своего каталога: `make run`
поднимает бота, конфиг лежит рядом с исходниками, а единственный интерфейс —
Telegram. Из этого растут две проблемы.

**Тулзу нельзя установить.** `bot.py` читает `config.toml` по пути
`Path(__file__).parent.parent`, то есть конфиг обязан лежать внутри клона. Пакет,
поставленный через `uv tool install`, окажется в стороннем каталоге и конфиг не
найдёт. Пока это не починено, ни CLI, ни приложение из части 2 не существуют.

**Упавшую сессию не поднять.** `claude` в панели запущен через `exec`: его смерть
уносит tmux-сессию целиком, и та просто исчезает из `list_sessions()`. Бот об
этом не узнаёт — пользователь обнаруживает потерю сам, открыв мёртвую ссылку.
История диалога при этом цела и лежит в `~/.claude/projects`, но добраться до неё
из бота нечем.

## Решения и их обоснование

| Решение | Выбор | Почему |
|---|---|---|
| Расположение конфига | `$CLAUDE_RC_CONFIG` → `~/.config/claude-rc/config.toml` → `./config.toml` | XDG-путь для установленной тулзы, `./config.toml` — чтобы разработка в клоне продолжала работать без переменных окружения. |
| Библиотека CLI | `argparse` | Новых зависимостей не тянем: тулзу ставят на машину, где каждая зависимость — риск конфликта. `--strict` mypy её понимает. |
| Источник истории диалогов | Каталог `~/.claude/projects/<slug>/*.jsonl` | Единственное место, где Claude Code хранит диалоги; из них же `--resume` берёт данные. Своего реестра не заводим — он разъедется с реальностью. |
| Проверка слага каталога | Сверять с полем `cwd` внутри jsonl | Кодировка слага недокументирована: `/` и `.` оба схлопываются в `-`, обратное преобразование неоднозначно. Вычисляем слаг, но подтверждаем содержимым. |
| Способ резюма | `claude --resume <id>` и `--continue` | Штатные флаги `claude`. Сочетание с `--remote-control` не описано в справке — см. «Риски». |
| Обнаружение падений | Опрос `list_sessions()` раз в 15 с | Событий от tmux нет, а `exec` делает исчезновение сессии единственным надёжным признаком смерти. Интервал берём заметно больше `_POLL_S`, чтобы не шуметь. |
| Память watcher'а | Только в памяти процесса | Восстановить достоверно, что упало, пока бот лежал, всё равно нельзя: сессии живут в tmux и рестарт бота их не трогает. Персистентность создала бы ложные отчёты. |

```
                   ┌──────────────┐   ┌──────────────┐
                   │  bot.py      │   │  cli.py      │   две морды
                   └──────┬───────┘   └──────┬───────┘
                          └─────────┬────────┘
        ┌────────────┬──────────────┼────────────┬────────────┐
        ▼            ▼              ▼            ▼            ▼
   ┌────────┐  ┌──────────┐  ┌──────────┐  ┌────────┐  ┌──────────┐
   │ paths  │  │ history  │  │  remote  │  │ watch  │  │  repos   │
   └────────┘  └────┬─────┘  └────┬─────┘  └───┬────┘  └──────────┘
                    │             │            │
```

`watch` зависит от `remote` и ничего не знает про Telegram: он отдаёт события,
а карточку рисует `bot.py`.

### `clauderc/paths.py`

Единственное место, где решается расположение файлов. Чистые функции, никакого
чтения содержимого:

```python
def config_file() -> Path      # первый существующий из цепочки; иначе XDG-путь
def log_file() -> Path         # ~/.claude-rc/claude-rc.log
def claude_projects() -> Path  # ~/.claude/projects
```

Цепочка для конфига: `$CLAUDE_RC_CONFIG`, затем `~/.config/claude-rc/config.toml`,
затем `config.toml` в текущем рабочем каталоге. Если не существует ни один —
возвращаем XDG-путь, чтобы сообщение об ошибке называло место, куда конфиг
положить, а не то, где его случайно искали.

`claude_projects()` уважает `$CLAUDE_CONFIG_DIR`, если он выставлен: Claude Code
им пользуется, и без этого мы бы читали чужой каталог.

Правка в существующем коде ровно одна: `bot.py:262` вместо
`load_config(root / "config.toml")` зовёт `load_config(paths.config_file())`.

### `clauderc/history.py`

Читающий модуль, знающий формат хранилища Claude Code.

```python
@dataclass(frozen=True)
class Conversation:
    session_id: str
    cwd: str
    updated_at: float   # mtime jsonl
    preview: str        # первое сообщение пользователя, обрезанное

def conversations(cwd: str, *, limit: int = 5) -> list[Conversation]
```

Порядок работы:

1. Слаг каталога: **каждый** символ вне `[A-Za-z0-9]` заменяется на `-`
   по отдельности, последовательности не схлопываются. Проверено на реальном
   каталоге: `/Users/n/.tg-claude-worktrees` даёт
   `-Users-n--tg-claude-worktrees` — два дефиса подряд от `/` и `.`. Это не то
   же самое, что `_UNSAFE` в `remote.py`, который схлопывает серии.
2. Каталога нет — пустой список, это нормальный случай, а не ошибка.
3. Для каждого `*.jsonl` читаем построчно, пока не встретим запись с полем `cwd`
   (первые строки — служебные: `last-prompt`, `mode`, `permission-mode`).
   Чтение ограничиваем первыми ~200 строками: файл бывает на сотни килобайт, а
   `cwd` и первое сообщение лежат в начале.
4. Если `cwd` в файле не совпадает с запрошенным по `realpath` — файл
   пропускаем. Это и есть защита от неоднозначного слага.
5. `preview` — первое сообщение с `type == "user"`, схлопнутые пробелы, обрез по
   80 символам. Не нашли — `"без названия"`.
6. Сортировка по `updated_at` убыванием, срез до `limit`.

Ошибки чтения отдельного файла (битый JSON, гонка с записью) пропускают файл и
пишут в лог на уровне `debug`: один испорченный диалог не должен ломать список.

### `clauderc/remote.py` — резюм при запуске

Сигнатура расширяется одним аргументом:

```python
async def launch(repo, cwd, *, timeout_s=90.0, resume: str | None = None) -> RemoteSession
```

`resume` принимает `None` (новый диалог), `"last"` (`--continue`) или id диалога
(`--resume <id>`). Значение попадает в командную строку через `shlex.quote`.
Остальное не меняется: та же панель с явным размером, та же чистка
`CLAUDE_CODE_*`, тот же `await_url` с `TrustRequired` и записью `@rc_url`.

Отдельно: `launch` по-прежнему возвращает существующую сессию, если в `cwd` уже
есть живая. Резюм в занятый каталог не поднимает вторую сессию — это сохраняет
инвариант «один каталог, одна сессия».

### `clauderc/watch.py`

```python
@dataclass(frozen=True)
class Died:
    name: str
    cwd: str

class Watcher:
    def expect_death(self, tmux_name: str) -> None
    async def run(self, on_died: Callable[[Died], Awaitable[None]]) -> None
```

`run` — бесконечный цикл: снять снимок `list_sessions()`, сравнить с предыдущим,
для каждой исчезнувшей сессии, чей `tmux_name` не отмечен через `expect_death`,
вызвать `on_died`. Пауза 15 с.

`expect_death` бот зовёт перед каждым намеренным гашением (кнопка `Stop`,
`/rckill`, `kill_all`). Отметка одноразовая: снимается, когда сессия
действительно исчезла, иначе повторный запуск в том же каталоге унаследовал бы
чужое «не сообщать».

Исключения внутри цикла ловятся и логируются: watcher не имеет права уронить
бота.

Первый снимок — базовый: событий не порождает, что бы в нём ни оказалось.
Иначе перезапуск бота при живых сессиях отчитался бы о падениях, которых не было.
Если `tmux` не поднят, `list_sessions()` возвращает пустой список — и это честно
означает, что RC-сессий нет.

### `clauderc/bot.py` — что меняется

1. **Конфиг** — через `paths.config_file()`.
2. **Развилка при запуске.** `▶️ Start Claude RC` в каталоге, где
   `history.conversations()` не пуст, показывает кнопки `New session`,
   `Continue last` и до пяти кнопок с превью диалогов. История пуста — запуск
   идёт как сейчас, без лишнего шага. Id диалога в `callback_data` не влезает
   рядом с префиксом не всегда — используем уже существующий механизм
   короткого токена (`pending`), как для выбора репозитория.
3. **Watcher.** Поднимается вместе с ботом. На `Died` шлёт карточку
   «сессия в `<cwd>` завершилась» с кнопкой `Resume`, ведущей в запуск с
   `resume="last"` в том же каталоге.
4. **Список при старте.** После `start_polling` бот шлёт владельцу карточки
   живых сессий со ссылками. Сессий нет — молчит.

### `clauderc/cli.py`

Entry point `claude-rc` в `[project.scripts]`. Подкоманды:

| Команда | Поведение |
|---|---|
| `bot` | запускает `bot.main()` на переднем плане |
| `sessions [--json]` | живые сессии: имя, каталог, аптайм, ссылка |
| `start [путь] [--branch B] [--resume last\|<id>]` | поднимает сессию, печатает ссылку |
| `stop <имя\|путь>` / `stop --all` | гасит |
| `doctor [--json]` | наличие `tmux`, `claude`, конфига, токена |
| `version` | версия из `importlib.metadata` |

`start` без пути работает в текущем каталоге. `--branch` создаёт worktree через
существующий `worktrees.py`.

`TrustRequired` в CLI обрабатывается вопросом на stdin: за терминалом сидит
человек, и его «да» — это и есть решение о правах на каталог, которое запрещено
принимать за него. При отсутствии tty (`not sys.stdin.isatty()`) команда падает
с понятным сообщением и кодом 2, сессию не гасит.

Коды возврата: `0` — успех, `1` — ошибка выполнения (`LaunchError`,
`WorktreeError`), `2` — ошибка окружения (нет конфига, нет tmux, нет tty).

`--json` есть у `sessions` и `doctor` — их читает приложение из части 2. Формат:
объект с ключом `sessions` / `checks`, не голый массив, чтобы поле можно было
добавить не ломая читателей.

`make run` начинает звать `claude-rc bot`. `python -m clauderc.bot` продолжает
работать: launchd-плист из README на него ссылается, и ломать его до части 3
незачем.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Конфига нет | CLI: код 2, сообщение с путём, куда положить, и ссылка на `config.example.toml` |
| `~/.claude/projects` нет | `conversations()` возвращает пустой список, развилка не показывается |
| Битый jsonl | файл пропущен, `debug` в лог |
| `--resume` с неизвестным id | `claude` завершится, `await_url` поднимет `LaunchError` с хвостом панели |
| tmux не поднят | `list_sessions()` пуст, watcher молчит |
| Падение внутри watcher'а | залогировано, цикл продолжается |

## Тестирование

Держим оба существующих стиля: подмена `remote._run` для tmux, настоящие
временные каталоги там, где мок был бы сложнее предмета.

- `test_paths.py` — цепочка поиска конфига, приоритет `$CLAUDE_RC_CONFIG`,
  уважение `$CLAUDE_CONFIG_DIR`. Через `monkeypatch` и `tmp_path`.
- `test_history.py` — рукописные jsonl во временном каталоге: порядок по mtime,
  срез по `limit`, пропуск файла с чужим `cwd`, пропуск битого JSON, превью из
  первого сообщения пользователя, пустой список для незнакомого каталога.
- `test_remote.py` — дополняется: `resume=None` не добавляет флагов,
  `resume="last"` даёт `--continue`, `resume="<id>"` даёт `--resume <id>` с
  экранированием; запуск с `resume` в занятый каталог возвращает существующую
  сессию, а не поднимает вторую.
- `test_watch.py` — на заглушке `list_sessions`: исчезновение даёт событие,
  исчезновение после `expect_death` не даёт, отметка снимается после смерти,
  исключение в опросе не прерывает цикл.
- `test_cli.py` — разбор аргументов и коды возврата на заглушках модулей;
  `--json` даёт валидный JSON с ожидаемыми ключами.

## Риски

**Сочетание `--remote-control` и `--resume` не описано в справке `claude`.**
Это первое, что проверяется — спайком, до всякого кода: поднять в tmux
`claude --remote-control --resume <id>` в каталоге с историей и посмотреть,
печатается ли ссылка и подхватывается ли диалог. Если не работает, запасной
вариант — `--session-id <uuid>` при первом старте: тогда id известен заранее,
но резюм чужих диалогов (созданных не через бота) станет недоступен, и пункт
`Pick…` из развилки уйдёт. Результат спайка определяет объём пункта 2 в
изменениях бота, поэтому план начинается с него.

**Формат хранилища Claude Code не является публичным API.** Смена раскладки
`~/.claude/projects` сломает `history.py`. Смягчение: модуль изолирован, при
любой неожиданности возвращает пустой список, и бот деградирует до сегодняшнего
поведения — запуск без развилки.

## Вне объёма

- Восстановление сессий после перезагрузки машины. tmux умирает вместе с
  системой; чтобы поднять всё заново, нужен персистентный реестр «что должно
  работать» — отдельная задача с отдельными решениями о том, что считать
  желаемым состоянием.
- Гейт прав на стороне бота. Граница из CLAUDE.md не двигается: единственная
  защита — `allowed_user_id`.
- Приложение и доставка — части 2 и 3.
