# claude-rc — настройка при первом запуске и публикация в Homebrew

Дата: 2026-08-19
Статус: дизайн утверждён, план не написан

Опирается на все три предыдущие части: команду `claude-rc`, приложение в меню-баре
и релизный workflow.

## Задача

Установка через Homebrew сегодня заканчивается тупиком. Проверено на коде:
`load_config` падает с `FileNotFoundError`, приложение трижды перезапускает бота и
показывает `crashed`, а `Reveal config` открывает пустой каталог. Ни одной подсказки,
что делать дальше. Публиковать в tap в таком виде нечего — человек получит
приложение, которое молча не работает.

Нужны две вещи, и они связаны: способ заполнить свои данные и способ поставить всё
это одной командой.

## Решения и их обоснование

| Решение | Выбор | Почему |
|---|---|---|
| Где заполняются данные | Визард `claude-rc setup` в терминале | Втрое меньше кода, чем нативное окно, логика на Python и потому тестируема, и работает на машине без графики. Приложение открывает Терминал с ним. |
| Проверка токена | Живой вызов `getMe` | Опечатка в токене иначе превращается в крэш-луп, который разбирают полчаса. Без сети — предупреждение, а не отказ: у человека может не быть интернета в момент настройки. |
| Как узнать `allowed_user_id` | Поймать из первого сообщения боту, ручной ввод — запасной | Иначе человек должен найти `@userinfobot`, написать ему и скопировать число. Самый ошибкоёмкий шаг из трёх. |
| Хранение токена | `config.toml` с правами `600` | Keychain «правильнее» для macOS, но читать его должен и Python-бот, а это лишний движущийся кусок и передача секрета между процессами. Права `600` — тот же уровень, что уже принят для лога. |
| Поведение приложения без конфига | Не запускать бота вовсе | Крэш-луп из трёх попыток не сообщает причину и выглядит как поломка. Отдельное состояние честнее. |
| Публикация | Тег → релиз → tap | Механика уже готова из части 3. Остаётся сделать её настоящей. |

## Архитектура

```
   claude-rc setup ──┐
                     ├──▶ ~/.config/claude-rc/config.toml (0600)
   человек ──────────┘              │
                                    ▼
   ClaudeRC.app ──▶ claude-rc doctor --json ──▶ config ok?
                          │                        │
                          │ нет                    │ да
                          ▼                        ▼
                   «Not configured»          запуск бота
                   открыть Терминал
                   с `claude-rc setup`
```

### `clauderc/setup.py`

Новый модуль. Вся логика визарда, кроме печати и чтения stdin, — чистые функции,
чтобы её можно было проверить тестом.

```python
@dataclass(frozen=True)
class Answers:
    bot_token: str
    allowed_user_id: int
    rc_roots: tuple[Path, ...]

def render_config(answers: Answers) -> str
def parse_roots(raw: str, *, default: Path | None) -> tuple[Path, ...]
def mask_token(token: str) -> str
def looks_like_token(value: str) -> bool
def default_roots() -> tuple[Path, ...]
```

`render_config` собирает текст `config.toml` с комментариями — тот же тон, что в
`config.example.toml`. Значения экранируются как строки TOML: токен содержит `:`,
а пути могут содержать что угодно.

`parse_roots` разбирает ввод (несколько путей через запятую), раскрывает `~`,
отбрасывает пустые, требует существования каждого. Несуществующий каталог —
ошибка на месте, а не через полчаса при первом `/repos`: `load_config` всё равно
не примет такой конфиг.

`mask_token` показывает первые символы до `:` и хвост, середину скрывает —
чтобы при повторном запуске человек узнал свой токен, но тот не попал целиком
ни на экран, ни в историю терминала.

`default_roots` предлагает `~/Documents`, если он есть, иначе домашний каталог.
Пустой ответ не принимается: `rc_roots` по умолчанию `~`, а обход на глубину 3 по
всему дому — долго и мусорно.

### Сетевая часть визарда

Две операции, обе в `clauderc/setup.py`, обе изолированы за узкими функциями,
чтобы тесты не ходили в сеть:

```python
async def verify_token(token: str) -> str | None   # имя бота или None
async def catch_user_id(token: str, *, timeout_s: float) -> int | None
```

`verify_token` зовёт `getMe`. Ошибка сети — возвращает `None`, и визард
предупреждает, но не блокирует: у человека может не быть интернета.
Неверный токен — тоже `None`, но об этом говорится отдельно, потому что
различие важно: в первом случае продолжать можно, во втором продолжать бессмысленно.

`catch_user_id` поднимает короткий поллинг и ждёт первого входящего сообщения,
возвращая id отправителя. Таймаут — чтобы визард не висел вечно. Не дождались или
человек отказался — ручной ввод.

**Граница, которую нельзя переходить:** визард не делает `getUpdates` в фоне и не
оставляет поллер после себя. Второй поллер того же токена ломает работающего бота —
на эти грабли проект уже наступал. Поэтому `catch_user_id` вызывается только по
явному согласию человека и только пока бот не настроен, то есть заведомо не запущен.

### `clauderc/cli.py` — подкоманда `setup`

```
claude-rc setup [--config PATH]
```

Без tty — отказ с кодом 2 и внятным сообщением: заполнять нечего, если некому
отвечать. Та же логика, что уже принята для диалога доверия каталогу.

Существующий конфиг не перезаписывается молча: значения показываются (токен
замаскирован), Enter оставляет как есть.

Коды возврата — прежний контракт: `0` успех, `1` не получилось сделать (например,
не удалось записать файл), `2` не с чем работать (нет tty, каталог из ответа
не существует).

### Приложение

Новое состояние `BotState.notConfigured`. Появляется, когда `claude-rc doctor --json`
говорит, что проверка `config` не прошла.

- бот в этом состоянии **не запускается вовсе** — крэш-луп из трёх попыток не
  сообщает причину и выглядит как поломка;
- в меню — пункт `Not configured — run setup`, открывающий Терминал с
  `claude-rc setup`;
- иконка контурная, как при погашенном боте.

Проверка делается на старте и при каждом открытии меню — человек мог настроить
всё в соседнем окне, и приложение должно это заметить без перезапуска.

Открытие Терминала: `NSWorkspace.open` с `Terminal.app` и путём к тулзе. Логика
«нужен ли setup» выносится в чистую функцию и покрывается тестом.

## Публикация

1. Версия `0.2.0` в `pyproject.toml`.
2. Тег `v0.2.0` — запускает готовый workflow из части 3.
3. Публичный репозиторий `nvinnikov/homebrew-tap`: `Formula/claude-rc.rb` и
   `Casks/claude-rc-app.rb` с настоящими `url` и `sha256`.
4. Блоки `resource` в формуле.

Обновление через `brew upgrade` работает: в cask есть `uninstall quit:`,
приложение гасится перед заменой.

## Ошибки

| Ситуация | Поведение |
|---|---|
| `setup` без tty | код 2, сообщение о том, что визард интерактивный |
| Нет сети при проверке токена | предупреждение, настройка продолжается |
| Токен отвергнут Telegram | сказано прямо, предложено ввести заново |
| Каталог из ответа не существует | переспрашиваем на месте, в файл не пишем |
| Не удалось записать конфиг | код 1, путь и причина |
| Конфиг есть, но битый | приложение показывает `Not configured`, визард стартует с пустых значений |

## Тестирование

- `test_setup.py` — чистые функции: `render_config` даёт TOML, который читается
  `load_config` обратно (круговой тест, самый ценный здесь); экранирование токена
  с двоеточием; `parse_roots` на нескольких путях, на `~`, на несуществующем;
  `mask_token` не показывает середину; `looks_like_token` на правдоподобных и
  мусорных значениях; `default_roots` при наличии и отсутствии `~/Documents`.
- `test_cli.py` — дополняется: `setup` без tty даёт 2; полный проход визарда на
  подменённом вводе пишет файл с правами `600`; повторный запуск с Enter на всех
  вопросах сохраняет прежние значения.
- Сетевые функции не тестируются вживую: подменяются заглушкой, проверяется
  реакция визарда на «ок», «неверный токен» и «нет сети».
- Swift: чистая функция «нужен ли setup» по выводу `doctor`.

## Риски

**`brew update-python-resources` может не работать для формулы, чей `url` ведёт на
GitHub Release, а не на PyPI.** Проверяется спайком до всего остального. Если не
сработает — блоки `resource` собираются из дерева зависимостей `uv`: работа
механическая, просто дольше.

**Первый настоящий релиз.** Тег запускает workflow, который до сих пор не
выполнялся ни разу. Проверка совпадения тега с версией и сборка бандла на
macOS-раннере проверены по отдельности, но не вместе и не на живом теге.

## Вне объёма

- Хранение токена в Keychain.
- Нативное окно настроек в приложении.
- Публикация в PyPI: тулза однопользовательская и завязана на локальный `claude`.
- Автообновление приложения помимо `brew upgrade`.
