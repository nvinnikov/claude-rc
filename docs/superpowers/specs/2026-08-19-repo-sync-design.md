# claude-rc — синхронизация репозиториев

Дата: 2026-08-19
Статус: дизайн утверждён, план не написан

## Задача

Часть локальных репозиториев отстаёт от `origin`, и человек узнаёт об этом, только
зайдя в каждый руками. Обновить пять штук — пять раз `cd`, `git pull`, посмотреть,
что получилось.

Навигация по дереву в боте уже есть: карточка `📁 PWD` показывает текущий каталог,
кнопку «наверх» и по кнопке на каждый подкаталог, а точка отмечает git-репозиторий.
Чего в ней нет — состояния репозиториев и способа сделать что-то сразу с несколькими.

Нужно: видеть, кто отстаёт, отметить нужные и подтянуть их одним действием, при
необходимости переключив на общую ветку.

## Решения и их обоснование

| Решение | Выбор | Почему |
|---|---|---|
| Какую ветку тянуть | Текущую в каждом репозитории; имя ветки — необязательный параметр | Единой главной ветки нет: где-то `dev`, где-то `master`, где-то `main`. Угадывать нельзя, а заставлять вводить имя каждый раз — лишний шаг для самого частого случая. |
| Способ обновления | Только `git pull --ff-only` | Перемотка либо проходит, либо отказывается. `merge` и `rebase` умеют оставить репозиторий в состоянии, из которого человек будет выбираться руками, а он в этот момент смотрит в телефон. |
| Грязные репозитории | Пропускаем целиком, не трогая | Незакоммиченная работа — то, что проект бережёт в первую очередь. `stash` не теряет её формально, но убирает из виду, и о ней забывают. |
| Переключение ветки | Только для чистых репозиториев | `git switch` **переносит** незакоммиченные изменения на другую ветку, если они не конфликтуют. Выглядит безобидно, а по факту недоделанная работа молча уезжает с одной ветки на другую. |
| Где живёт выбор | Отдельный режим карточки навигации | Кнопки навигации проваливают внутрь. Смешивать это с постановкой галочек — путать два разных действия в одном месте. |
| Что показываем | Ветка, отставание, опережение, грязь | Без этого непонятно, какие галочки ставить. |

## Архитектура

```
   clauderc/sync.py            bot.py                      cli.py
   ─────────────────           ──────                      ──────
   status(repo)        ◀────── карточка выбора      ◀───── claude-rc sync
   sync(repo, branch)  ◀────── отчёт по строке              --branch, пути
        │
        └── worktrees._git (уже есть)
```

`sync.py` ничего не знает ни про Telegram, ни про терминал: он отвечает на два
вопроса — «в каком состоянии репозиторий» и «подтяни его».

### `clauderc/sync.py`

```python
@dataclass(frozen=True)
class RepoStatus:
    path: Path
    branch: str          # текущая ветка или "HEAD" в отсоединённом состоянии
    dirty: bool
    ahead: int           # свои коммиты, которых нет в upstream
    behind: int          # коммиты upstream, которых нет у нас
    upstream: str | None # None — у ветки нет upstream

@dataclass(frozen=True)
class SyncResult:
    path: Path
    outcome: Outcome     # updated | already | skipped | failed
    detail: str          # человекочитаемая причина
    branch: str          # ветка, на которой оказались

async def status(repo: Path) -> RepoStatus | None
async def sync(repo: Path, *, branch: str | None, fetch: bool = True) -> SyncResult
```

`status` возвращает `None`, если каталог не рабочая копия git: вызывающий сам решает,
показывать его или пропустить.

Отставание и опережение считаются одним вызовом
`git rev-list --left-right --count HEAD...@{upstream}`. Ветки без upstream дают
`upstream=None`, `ahead=behind=0` — это не ошибка, а нормальное состояние локальной
ветки, и в отчёте оно так и называется.

Порядок работы `sync` для одного репозитория:

1. `git fetch` — безопасно всегда, ничего в рабочем дереве не меняет;
2. грязный — `skipped`, причина «незакоммиченные изменения»; дальше не идём;
3. имя ветки задано и отличается от текущей:
   - ветка есть локально — `git switch <branch>`;
   - ветки нет локально, но есть `origin/<branch>` — `git switch -c <branch> --track origin/<branch>`;
   - нет нигде — `skipped`, причина «ветки нет ни локально, ни в origin»;
4. `git pull --ff-only`;
5. итог: перемотались — `updated` с числом подтянутых коммитов; уже совпадаем —
   `already`; отказ перемотки — `failed` с причиной «ветки разошлись».

**Границы, которые не двигаем.** `sync` никогда не делает `merge`, `rebase`, `stash`,
`reset` и `checkout -f`. Любая операция, способная перезаписать или спрятать работу
человека, вне этого модуля.

### Бот

На карточке `📁 PWD` появляется `🔄 Sync`, если в текущем каталоге есть хотя бы один
git-репозиторий. Нажатие переводит карточку в режим выбора:

```
🔄 /Users/nvinnikov/Documents/Flybo
  ☑ flybo-ai        dev ↓3
  ☐ flybo-arch-v2   master ✓
  ☑ qa_tests        dev ↓12
  ☐ preorder        feature/x ✎
────────────────────────────
  Все · Никого
  Ветка: (текущая)
  ⤵️ Подтянуть · Отмена
```

Тап по строке переключает галочку. `Ветка:` открывает ввод имени; пустое значение —
остаться на текущей. `⤵️ Подтянуть` запускает работу и присылает отчёт строкой на
репозиторий.

Обозначения: `↓N` отстаёт, `↑N` опережает, `✎` грязный, `✓` в порядке,
`⚠` нет upstream.

Выбор живёт в памяти процесса, привязан к сообщению. Перезапуск бота его теряет — и
это правильно: восстанавливать наполовину сделанный выбор опаснее, чем начать заново.

**`callback_data`**: индекс в текущем списке, как уже сделано для навигации. Пути и
имена туда не кладём — 64 байта.

Состояния читаются параллельно (`asyncio.gather`), иначе каталог на два десятка
репозиториев будет открываться заметно долго: каждый `status` — три вызова git.

### CLI

```
claude-rc sync [--branch B] [--fetch/--no-fetch] [пути...]
```

Без путей — репозитории в текущем каталоге. Без `--branch` — текущая ветка каждого.
Вывод — строка на репозиторий, в конце сводка. Код возврата `0`, если ни один не
`failed`; `1`, если хоть один; `2` — не с чем работать (репозиториев не нашлось).

`--no-fetch` нужен, чтобы посмотреть состояние без обращения к сети.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Каталог не репозиторий | пропускаем, в списке не показываем |
| `fetch` не прошёл (нет сети, нет доступа) | `failed`, причина из git, остальные репозитории обрабатываются |
| Грязный | `skipped`, работа не тронута |
| Ветки разошлись | `failed`, «перемотка невозможна» — предлагаем разобраться руками |
| Ветки нет нигде | `skipped` |
| Отсоединённый HEAD | `skipped`, причина названа |
| Нет upstream | `skipped` при `pull`, в состоянии показывается `⚠` |

## Тестирование

`test_sync.py` — на настоящих временных репозиториях, как уже сделано для worktree:
git быстрый, а мокать его пришлось бы так подробно, что тест перестал бы что-либо
доказывать. Локальный «origin» заводится как отдельный каталог с `git init --bare`,
сеть не нужна.

Случаи: отстающий перематывается; совпадающий даёт `already`; грязный не трогается
и остаётся грязным (проверяем содержимое файла до и после); разошедшийся даёт
`failed` и **не меняет** HEAD; переключение на существующую ветку; на ветку из
`origin`; на несуществующую — `skipped`; отсоединённый HEAD; ветка без upstream.

Отдельный тест: после `sync` грязного репозитория `git status --porcelain` совпадает
с тем, что было до. Это главное свойство модуля, и оно должно проверяться прямо.

## Вне объёма

- `push`: отправлять чужую работу автоматически опаснее, чем подтягивать.
- `stash`, `merge`, `rebase`, разрешение конфликтов.
- Синхронизация из меню-бара: там тумблер бота, а не работа с репозиториями.
- Планировщик «подтягивать раз в час»: сначала посмотрим, как это работает руками.
