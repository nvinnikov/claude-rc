# tg-claude как лаунчер Remote Control

Дата: 2026-07-30

## Зачем

Первая версия бота была чатом с агентом: сообщение из Telegram → прогон Claude Agent SDK →
ответ в чат. На практике это неудобно — держать контекст сессии, читать длинные ответы
и подтверждать права с телефона хуже, чем то же самое в приложении Claude.

У Claude Code есть встроенный Remote Control: `claude --remote-control <name>` поднимает
интерактивную сессию и печатает ссылку вида `https://claude.ai/code/session_<id>`, по которой
та же сессия открывается в вебе и в мобильном приложении.

Отсюда новая роль бота: **не разговаривать, а запускать**. С телефона одна команда —
и приходит ссылка, дальше работа идёт в приложении Claude.

## Что убирается

Чат-режим уходит целиком, вместе с обслуживающей его машинерией:

- `runner.py` — обёртка над Claude Agent SDK;
- `sessions.py`, `store.py` — менеджер сессий и SQLite;
- `rules.py`, `approvals.py` — гейт прав и кнопки подтверждения;
- `shell.py` — режим `!cmd`;
- команды `/new`, `/cd`, `/pwd`, `/stop`, `/status`, обработчик произвольного текста;
- зависимость `claude-agent-sdk` (теперь запускается CLI напрямую), файл `rules.toml`, `sessions.db`.

Из `render.py` остаётся только `chunks` — список репозиториев может не влезть в лимит Telegram.

## Где живёт сессия

`claude --remote-control` — интерактивная команда: без tty она уходит в режим `--print`
и падает с `Input must be provided either through stdin or as a prompt argument`.
Значит нужен псевдотерминал.

Рассматривались два варианта. `pty.openpty()` внутри процесса бота не требует зависимостей,
но привязывает сессии к жизни бота: launchd перезапустил бота — все ссылки протухли.
**Выбран tmux**: сессия принадлежит tmux-серверу, а бот только отдаёт ему команды.

Что это даёт:

- сессии переживают рестарт бота — реестр не в памяти, а в самом tmux;
- к любой из них можно подсесть с машины: `tmux attach -t rc-<имя>`;
- пропадает целый класс расхождений «в реестре есть, а процесса нет» — нечего синхронизировать.

Цена — внешняя зависимость (`brew install tmux`) и то, что ссылку приходится не читать
потоком, а поллить через `capture-pane`.

## `tgclaude/remote.py`

Тонкая обёртка над `tmux`, без состояния в памяти. Имя tmux-сессии — `rc-<репо>`,
префикс отделяет наши сессии от чужих; `.` и `:` из имени вычищаются, tmux их не принимает.

`launch(repo, cwd, timeout_s)`:

1. `tmux new-session -d -s rc-<репо> -x 120 -y 40 -c <cwd> <команда>`;
2. поллит `tmux capture-pane -p -J -t '=rc-<репо>:'` раз в 0.7с, ищет
   `https://claude\.ai/code/session_[A-Za-z0-9_-]+`;
3. найденное кладёт в user-опцию `@rc_url` и возвращает сессию;
4. не нашёл за таймаут или панель умерла — гасит сессию и поднимает `LaunchError`
   с хвостом вывода, чтобы причина была видна прямо в чате.

Три детали, проверенные на живом запуске (Claude Code 2.1.220, tmux 3.7b):

1. **Размер панели задаём явно** (`-x 120 -y 40`). У панели без подключённого клиента
   размер по умолчанию мелкий, и TUI переносит строки так, что ссылка рвётся пополам.
   Флаг `-J` у `capture-pane` дополнительно сшивает перенесённые строки.
2. **Ссылку нельзя хранить только в панели.** TUI её перерисовывает и затирает,
   а после рестарта бота её неоткуда взять — поэтому `@rc_url`.
3. **`CLAUDE_CODE_*` надо вычищать внутри панели.** tmux-сервер мог быть поднят из-под
   Claude Code; унаследованный `CLAUDE_CODE_CHILD_SESSION` заставляет claude написать
   «Transcript saving is off», и новая сессия останется без истории. Команда панели
   начинается с цикла `unset` по всем переменным с этим префиксом.

Точечная деталь синтаксиса tmux 3.7: `=` (точное совпадение имени) работает как
`-t '=имя'` для `has-session`/`kill-session` и как `-t '=имя:'` там, где ожидается
target-pane (`capture-pane`, `set-option`). Без `=` `rc-oms` совпал бы с `rc-oms-2`.

Остальное — запросы к tmux: `list-sessions -F` с полями `session_name`, `session_path`,
`session_created`, `@rc_url` даёт весь список разом; `kill-session` гасит.

### Ключ сессии — каталог, а не имя

Первая версия искала сессию по имени репозитория, и это ломалось на двух клонах
одного репозитория в разных местах дерева: `/rc claude-rules` молча возвращал ссылку
на сессию в чужом каталоге. Поэтому `find(cwd)` сравнивает `realpath`, а имя tmux-сессии
осталось только для отображения и `/rckill`. При коллизии имён к базовому добавляется
шестизначный хвост от хеша пути (`rc-claude-rules-a3f1c2`).

### Диалог доверия каталогу

В незнакомом каталоге (а свежий worktree всегда незнакомый) claude сначала спрашивает
«Is this a project you created or one you trust?» и до ответа ссылку не печатает.
Штатно диалог пропускается только в `--print`, а Remote Control требует интерактива.

Отвечать за пользователя бот не должен — это решение о правах на каталог. Поэтому
`await_url` поднимает `TrustRequired`, **не гася сессию**, бот присылает кнопку
«Доверяю», и только после нажатия `confirm_trust` шлёт `Enter` в панель. Ожидание
продолжается с `watch_trust=False`: после Enter диалог ещё мгновение виден на экране,
и повторная проверка приняла бы его за неотвеченный.

## `tgclaude/worktrees.py`

`/rc <репо> <ветка>` — ответ на вопрос «а если нужны две сессии по одной репе».
В одном каталоге они дерутся за индекс, ветку и файлы, поэтому вторая уходит
в git worktree под `worktree_root`.

`ensure(repo, branch, root)` сначала пробует существующую ветку (git сам подхватит
remote-only через DWIM), не вышло — создаёт новую от `HEAD`. Готовый каталог
переиспользуется, а не пересоздаётся.

Удаление намеренно консервативное: `remove` отказывается, если в worktree есть
незакоммиченные изменения или коммиты, которых нет ни на одном remote
(`git log HEAD --not --remotes` — это покрывает и ветку без upstream). Перебить
отказ можно только явным `force`. `/rckill` worktree не трогает вообще: сессия
эфемерна, а рабочая копия может содержать несохранённую работу.

## `tgclaude/repos.py`

В конфиге появляется `rc_roots` — список корней сканирования. Обход на глубину `scan_depth`
(по умолчанию 3, столько нужно, чтобы достать `<монорепо>/services/<сервис>`), целью
считается каталог с `.git`. Сами корни тоже валидные цели: рабочий
зонт без собственного `.git`, но запускаться в нём осмысленно. Скрытые каталоги и тяжёлый
мусор (`node_modules`, `vendor`, `Library`, …) пропускаются.

`resolve(query, candidates)`: точное совпадение имени — один элемент, иначе все частичные.

## Команды бота

| Команда | Действие |
|---|---|
| `/rc <репо>` | поднять RC-сессию, ответить ссылкой-кнопкой |
| `/rc <репо> <ветка>` | то же, но в отдельном worktree |
| `/rc` | живые сессии |
| `/repos` | доступные репозитории |
| `/rckill <имя>` | погасить сессию (без имени — все) |
| `/wt` | созданные worktree и их состояние |
| `/wtrm <имя> [force]` | удалить worktree |

Неоднозначный запрос — inline-кнопки с выбором (токен в `callback_data`, потому что
туда влезает 64 байта и полный путь не поместится). Повторный `/rc oms` при живой сессии
возвращает существующую ссылку, а не поднимает вторую. Обход файловой системы кэшируется
на 60 секунд и уходит в `asyncio.to_thread`, чтобы не блокировать поллинг Telegram.

Авторизация остаётся как была: fail-closed по `allowed_user_id`, `from_user=None` → отказ.

## Границы

**Гейта прав больше нет, и `rules.toml` удалён.** RC-сессия интерактивная, разрешения
выдаются в приложении Claude. Тот, кто прошёл проверку `allowed_user_id`, получает
полноценный Claude Code на машине со всеми токенами в `~`.

**Мак не должен спать**, иначе бот не ответит: `sudo pmset -c sleep 0`.

**launchd-задаче нужен явный `PATH`**: по умолчанию он голый, и ни `tmux`, ни `claude`
не находятся.
