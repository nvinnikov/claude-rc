# CLAUDE.md

Инструкции для Claude Code при работе в этом репозитории.

## Что это

Telegram-бот, который поднимает на локальной машине сессии Claude Code с включённым
Remote Control и присылает ссылку. Сам он в диалоге не участвует — только запускает.

Ключевое ограничение, из которого растёт вся конструкция: `claude --remote-control` —
**интерактивная** команда. Без tty она уходит в режим `--print` и падает с
`Input must be provided either through stdin or as a prompt argument`. Поэтому каждая
сессия живёт в своей tmux-сессии: заводится как `rc-<имя>` и переименовывается в свой
`session_…`, как только появилась ссылка. Бот только отдаёт tmux команды.

## Команды

```bash
make check       # локальное зеркало CI: lint + typecheck + test
make lint        # ruff format --check + ruff check
make format      # ruff format + ruff check --fix
make typecheck   # mypy --strict
make test        # pytest
make run         # запустить бота вручную
make app         # собрать app/build/ClaudeRC.app (Swift, без Xcode)
make app-test    # тесты Swift-пакета в app/
make install       # тулзу + приложение одной командой — основной способ поставить себе
make install-tool  # только тулзу claude-rc, без приложения (например, машина без графики)
make install-app   # то же, что install: install-tool + сборка и установка приложения

uv run pytest tests/test_remote.py::test_launch_stores_url_in_tmux_option  # один тест

uv run claude-rc                 # те же действия бота из терминала (`claude-rc bot` = `make run`)
uv run claude-rc update --check  # как поставлено, какая версия, есть ли новее
uv run claude-rc whoami --json   # чья это сессия — из неё же самой или из подкаталога
uv run claude-rc send oms@fix '/mcp' --tail 20              # набрать текст, посмотреть хвост панели
uv run claude-rc restart oms@fix --mode bypassPermissions   # погасить и поднять заново с --resume
uv run claude-rc --host m1 sessions --json                  # то же самое, но на другой машине
```

Гейт должен быть зелёным перед коммитом. `mypy --strict` включён на весь код и тесты —
новые функции аннотируем, `Any` не протаскиваем.

## Структура

| Модуль | Ответственность |
|---|---|
| `clauderc/remote.py` | всё общение с tmux: поднять сессию, добыть ссылку, погасить |
| `clauderc/passport.py` | паспорт сессии: одна структура, рендер в HTML для бота, текст для CLI, JSON для стюарда |
| `clauderc/state_probe.py` | состояние сессии по снимку панели (idle/working/needs_input/dead/unknown), слушающие порты |
| `clauderc/actions.py` | действия над сессией: `send`, `tail`, `send_and_tail`, `rename`, `restart` |
| `clauderc/proxy.py` | `--host`: выполнить команду на другой машине по ssh |
| `clauderc/forward.py` | ssh-туннели к портам сессии на `--host`, pid-файлы под `~/.claude-rc/forwards` |
| `clauderc/worktrees.py` | git worktree под ветку: создать, осмотреть, удалить, назвать (`label`) |
| `clauderc/browse.py` | навигация по дереву каталогов (`cd`/`ls`) |
| `clauderc/repos.py` | обход `rc_roots` в поисках git-репозиториев |
| `clauderc/state.py` | текущий каталог между перезапусками (JSON) |
| `clauderc/config.py` | чтение `config.toml` |
| `clauderc/bot.py` | aiogram-хендлеры, карточки и кнопки |
| `clauderc/paths.py` | где лежат конфиг, лог и хранилище диалогов Claude Code |
| `clauderc/history.py` | диалоги Claude Code для каталога (для резюма) |
| `clauderc/watch.py` | опрос tmux: замечает исчезнувшие сессии, метит намеренные гашения |
| `clauderc/cli.py` | команда `claude-rc`: те же действия из терминала |
| `clauderc/update.py` | канал установки и команда обновления для него |
| `clauderc/sync.py` | состояние репозитория относительно origin и подтягивание — общее для бота и CLI |
| `app/` | Swift-пакет `ClaudeRCMenu`: приложение в меню-баре, владеющее процессом бота |

Права и подтягивание решаются до запуска, а не во время: `permission_mode` уходит в
`--permission-mode`, `pull_before_start` — в `sync` **до** создания worktree, потому что
`git worktree add` ветвится от текущего HEAD.

Версии и каналы установки считает только `update.py`; приложение читает готовый ответ
через `claude-rc update --check --json` (`Updater.swift`), чтобы не завести второй
источник правды.

Вся логика — в модулях, `bot.py` только собирает из неё сообщения. Новую механику
кладём в модуль и покрываем тестом, а не в хендлер.

## Грабли, на которые уже наступали

**Ярлык сессии один на все поверхности.** `repo@branch` уходит разом в
`--remote-control` (как сессия зовётся в приложении Claude), в `-n` (рамка ввода,
`/resume`-пикер, заголовок терминала), в имя tmux-сессии и в карточку бота. Сами по
себе поверхности расходятся: без `-n` приложение подставляет авто-название, а каталог
worktree — слаг (`oms-wt-feature-x`), который говорит меньше, чем ветка, из которой он
получен. Ярлык живёт в user-опции tmux `@rc_label` и ставится при `new-session`, а не
после ссылки: сессия, умершая до неё, должна называться в отчёте о смерти так же, как
её звали при запуске.

**`claude-rc whoami` — то, чем агент на машине узнаёт себя.** Ищет по каталогу **и
его родителям**: агент почти никогда не стоит в корне worktree, и точный `find(cwd)`
из подкаталога сессию бы не нашёл. `--json` отдаёт всё соответствие разом — ярлык,
`session_…`, ссылку, готовую команду подсадки.

**Ключ сессии — рабочий каталог, а не имя.** Имя репозитория в дереве не уникально
(два клона одного репо), и поиск по имени возвращал ссылку на сессию в чужом каталоге.
`find(cwd)` сравнивает `realpath`; имя tmux-сессии осталось только для отображения.

**Синтаксис target в tmux 3.x неоднороден.** `=имя` (точное совпадение) работает для
`has-session`/`kill-session`, а там, где ожидается target-pane (`capture-pane`,
`set-option`), нужно `=имя:`. Без `=` `rc-oms` совпадёт с `rc-oms-2`.

**Ссылку нельзя хранить только в панели.** TUI перерисовывает её и затирает, а после
рестарта бота взять неоткуда — поэтому она кладётся в user-опцию tmux `@rc_url`.

**Размер панели задаём явно** (`-x 120 -y 40`). У панели без подключённого клиента
размер мелкий, и TUI переносит строки так, что ссылка рвётся пополам.

**Команда подсадки отцепляет прочих клиентов (`-d`).** Следствие предыдущего пункта:
второй tmux-клиент с узким окном ужимает панель всем сразу, и TUI переверстывается под
руками у того, кто работает прямо сейчас. Приложения Claude это не касается — оно
говорит с сессией через API, а не через tmux, поэтому `-d` безопасен.

**Сессия переименовывается в id Claude, как только появилась ссылка.** Сразу назвать
её так нельзя: id выдаёт сервер, и до первой печати в панели его не существует —
поэтому сессия создаётся под именем от каталога и переименовывается по факту. Отсюда
два следствия. `list_sessions` узнаёт своих по префиксу `rc-` **или** по выставленному
`@rc_url`: по одному префиксу потерялись бы переименованные, по одной опции — умершие,
не дождавшись ссылки. И `Watcher` не считает смертью исчезнувшее имя, пока жива сессия
с тем же рабочим каталогом, — иначе каждый запуск отчитывался бы падением.

**Имя tmux-сессии меняется у неё под ногами.** Переименование происходит по факту
появления ссылки, поэтому запомненное имя (в токене кнопки, в переменной, в кэше)
к моменту использования может уже не существовать. Всё, что переживает показ карточки,
держит рабочий каталог и добывает имя заново.

**Имя сессии (`RemoteSession.name`) — ярлык, а не ключ.** Оно берётся от каталога и у
трёх клонов одного репозитория одинаково. Всё, что принимает цель от человека
(`/rckill`, `claude-rc stop`), идёт через `remote.resolve` и на неоднозначность
отвечает списком id, а не гасит первую попавшуюся.

**Новый ключ конфига надо добавить в `_EXTRA_KEYS`.** Визард переписывает `config.toml`
с нуля и переносит только ключи из этого списка. Ключ, забытый в нём, молча стирается
при следующем `claude-rc setup` — вместе с тем, что человек правил руками.

**`CLAUDE_CODE_*` чистим внутри панели.** tmux-сервер мог быть поднят из-под Claude
Code; унаследованный `CLAUDE_CODE_CHILD_SESSION` стартует сессию с «Transcript saving
is off», то есть без истории.

**Диалог доверия каталогу не обходим молча.** В незнакомом каталоге claude ждёт ответа
и до него ссылку не печатает. `await_url` поднимает `TrustRequired`, не гася сессию,
и ответ уходит в панель только после нажатия кнопки человеком. Автоподтверждение —
не наш выбор: это решение о правах на каталог.

**Отвечаем на диалог доверия номером пункта, а не Enter.** Enter подтверждает тот
пункт, который подсвечен, а какой подсвечен — решает claude, и это уже менялось.
Подсвеченным оказался отказ: claude вышел, tmux-сессия кончилась вместе с ним, и
человек получил «сессия завершилась, не отдав ссылку» в ответ на собственный тап
«доверяю». Номер печатает сам диалог — на него и опираемся.

**В сообщении о смерти сессии — последняя удачная панель, а не вывод неудачного
`capture-pane`.** Когда сессии уже нет, tmux печатает `can't find session`, и раньше
именно это уезжало человеку вместо того, что было на экране перед смертью, — то есть
вместо единственной подсказки, почему всё кончилось.

**Telegram даёт `InaccessibleMessage`** для слишком старых сообщений — у него нет
`edit_text`. В колбэках сужаем через `_live_message(query)`, а не через
`if query.message is None`.

**В `callback_data` влезает 64 байта.** Пути и имена туда не кладём: либо индекс в
текущем списке, либо короткий токен из словаря.

**Заявки на ответ (`name_pending`, `rename_pending`, `branch_pending`) живут в
памяти процесса, а не в `state.py`.** Связывает ответ с вопросом сам Telegram —
ForceReply плюс `reply_to_message`, — и это способ проекта; наполовину сделанный
выбор переживать перезапуск не должен. Но ForceReply в чате перезапуск переживает,
и ответ на него после рестарта не находит заявки: молчать нельзя — на своё же
сообщение отвечаем «запрос устарел», на чужое по-прежнему молчим.

**Слаг каталога в `~/.claude/projects` — посимвольный.** Каждый символ вне
`[A-Za-z0-9]` заменяется на `-` по отдельности, серии не схлопываются:
`/Users/n/.x` даёт `-Users-n--x`, два дефиса подряд. Регексп `_UNSAFE` из
`remote.py` серии как раз схлопывает — скопировать его сюда нельзя. И сам слаг
неоднозначен, поэтому `history` подтверждает попадание полем `cwd` внутри файла.

**Погашенную сессию `Watcher` вычёркивает из снимка, а не помечает меткой.**
Поллер считает смертью исчезновение из снимка, поэтому убрать сессию из снимка —
точный способ сказать «эта смерть ожидаемая». Метка рядом со снимком всегда хуже:
она переживает сессию, а сессия на её месте появляется мгновенно. `restart` гасит и
поднимает в одном каталоге, и различить их нечем — имя меняется под ногами,
`#{session_created}` идёт целыми секундами, а `#{session_id}` начинает нумерацию
заново, если гасимая была на сервере единственной и сервер ушёл вместе с ней.
Поэтому `Watcher.kill` принимает `cwd` и `tmux_id`, и все вызывающие передают —
сессию они и так держат. Метка по имени осталась одна и только на гонку: `poll` мог
запросить `list-sessions` до гашения, а разложить ответ по снимку уже после.

**`tmux_id` — удостоверение экземпляра сессии, `created_at` им быть не может.**
`#{session_created}` — целые секунды, а гашение с запуском при `restart` в одну
секунду и укладываются: у перезапущенной сессии то же время создания. `#{session_id}`
(`$3`) переименование переживает, а перезапуск — нет, поэтому на нём построены
проверка «переименовали, а не потеряли» в `Watcher.poll` и `_same_session`, которым
бот сверяет кнопку карточки с живой сессией. Не путать с id сессии Claude
(`session_…`): тот живёт в имени tmux после переименования и в `passport.session_id`.

**Гасить сессию мимо `Watcher` нельзя.** Watcher считает падением любое
исчезновение сессии, которое он не пометил как ожидаемое. `remote.kill_tmux`
напрямую из хендлера даст пользователю карточку «сессия упала» сразу после того,
как он сам нажал Stop.

**Приложение из автозапуска получает голый `PATH`.** Бот, поднятый им как дочерний
процесс, не найдёт ни `tmux`, ни `claude`, если не подставить `PATH` явно —
`CLILocator.childEnvironment` существует ровно для этого. Те же грабли раньше
обходились руками в launchd-плисте.

**Установка из клона и из git выглядят одинаково.** `make install` зовёт
`uv tool install --force .`, и окружение получается ровно такое же, как у установки
из git-URL. Различает их только квитанция `uv-receipt.toml` рядом с окружением: у
установки из каталога там `directory`, у установки из git — `git`. Без неё обновление
основного способа установки уходило бы на master вместо клона, а приложение в
`/Applications` не переустанавливалось бы вовсе.

**Список режимов прав списан с `claude --help`, а не с документации.** `default` —
имя ручного режима для `permissions.defaultMode` в settings.json, и в примерах
документации он встречается как значение флага, но `--permission-mode` его не
принимает и с ним не стартует. Внести его в белый список значит пропустить ровно ту
ошибку, ради которой список заведён. Ручной режим у флага зовётся `manual`.

**Клон опознаётся по имени пакета, а не по наличию `pyproject.toml`.** `uv run claude-rc`
из чужого проекта даёт окружение, рядом с которым лежит *его* `pyproject.toml`. Приняв
его за наш клон, обновление ушло бы тянуть и собирать чужой репозиторий.

**Автообновление помнит версию, которую уже пробовало.** Иначе неудачная попытка
зацикливается: обновление гасит приложение, оно открывается заново, проверка снова видит
ту же версию доступной и снова открывает Терминал. Повторить ту же версию можно руками —
пункт меню это позволяет всегда, и включение тумблера память сбрасывает.

**Обновление гасит приложение, поэтому идёт из Терминала.** Переустановка кладёт файлы
под работающим процессом — и `make install`, и каска сначала убивают приложение. Дочерний
процесс, запущенный из меню, умер бы вместе с ним на середине, поэтому скрипт открывается
в Терминале, гасит приложение сам (SIGTERM, чтобы бот остановился корректно) и открывает
заново — безусловно, даже если обновление не вышло.

**Два поллера одного токена ломают бота молча.** Telegram отдаёт конфликт, и оба
экземпляра работают через раз. Перед запуском своего процесса приложение ищет чужой
и, найдя, показывает его pid вместо запуска.

**`sync --branch` в worktree мог обнулить блокировку `wtrm`.** `blockers` у
worktree считаются по текущей ветке (неотправленные коммиты, dirty). Переключить
ветку — и коммиты остаются на старой ветке (не теряются, `git branch` их видит),
а `unpushed` для новой ветки честно нулевой: `wtrm` без `force` перестал бы
отказывать. `sync.py` отказывается переключать ветку в **любом** worktree —
не только там, где `remote.find` видит живую RC-сессию: это две независимые
проверки (`git rev-parse --git-common-dir` отличается от `.git`, если каталог
worktree), и хватает одной сработавшей. Живая сессия — отдельная причина не
трогать ветку (человек работает прямо сейчас), а не единственная защита.

**`.requiresApproval` от `SMAppService.mainApp.register()` — не ошибка.** Это
успех, ожидающий подтверждения человека в System Settings. Принять его за ошибку
и завести поверх ручной LaunchAgent значит получить два механизма автозапуска и
двойной старт бота. Мы на этом уже спотыкались.

**`send-keys` без `-l` — это клавиши, а не текст.** `actions.send` шлёт текст в панель
через `tmux send-keys -l -t =<имя>:` отдельно от `Enter`: без `-l` `Up`, `C-c` и подобные
трактуются как имена клавиш, а не как буквы. `-l` защищает текст, `Enter` уходит вторым
вызовом — так `--no-enter` может его пропустить для ответа одной клавишей на диалог.

**`send` проверяет код возврата `send-keys` и для `Enter`, не только для текста.**
Каждый из двух вызовов к панели может не дойти по отдельности; непроверенный сбой
второго выглядел бы как набранный, но неотправленный ответ на диалог.

**`restart` не гасит сессию мимо `Watcher`.** Как и прямой `remote.kill_tmux` из
хендлера, гашение в обход даёт человеку карточку «сессия упала» сразу после того, как
он сам нажал кнопку перезапуска, — правило то же, что уже действует для `stop`.

**`restart` держит `cwd` и `session_id`, а не имя.** Имя tmux-сессии меняется под
ногами, как только появилась ссылка (см. выше), поэтому цель для повторного `--resume`
после гашения ищется по рабочему каталогу и запомненному id, а не по имени, которое к
этому моменту могло уже перестать существовать.

**Состояние — это то, что видно на панели, а не то, что знает claude.** У tmux нет
событий, у claude нет API статуса; `state_probe.probe` разбирает один `capture-pane` по
шаблонам: пустая рамка ввода — `idle`, спиннер без рамки — `working`, нумерованный
диалог или `(y/n)` — `needs_input`. Шаблон, который не подошёл ни разу, даёт `unknown`,
а не догадку: сломанный обновлением claude шаблон обязан быть заметен явно, а не тихо
выдавать неверный `idle`.

**Код возврата `lsof` — не признак ошибки при поиске портов.** Один из процессов
панели мог уже умереть между `pgrep` и `lsof`: тогда `lsof` возвращает код 1, но всё
равно печатает порты остальных живых. Код игнорируется, кроме 127 (`lsof` не найден
вовсе) — иначе поиск портов ломался бы там, где сессия просто ничего не запустила.

**`actions` и `state_probe` ходят через `remote._run`, а не заводят свою подмену.**
Второй сеанс замены tmux-вызовов развёл бы поведение тестов на разные модули
незаметно для ревью — подмена в тестах должна быть одна на весь код, говорящий с tmux.

**`forward` — единственная команда, которая выполняется на клиенте, а не на сервере
`--host`.** Туннель должен слушать порт там, где потом откроют
`http://localhost:<port>`, то есть локально, — оговорённое исключение из правила
«`--host` = выполни там», и README называет его отдельно, а не оставляет угадывать.

**`forward` проверяет хост раньше, чем трогает pid-файл, гасит процесс раньше
`unlink`, и делает `poll()` сразу после `Popen`.** Порядок важен по трём разным
причинам: неправильный хост не должен превратиться в путь до чужого pid-файла;
`unlink` раньше `kill` оставил бы процесс без присмотра, если гашение не удалось;
`poll()` сразу после запуска отличает живой туннель от ssh, упавшего на старте
(например, из-за уже занятого порта).

**`--host` без значения — ошибка, а не локальный запуск.** Забытый аргумент
(`claude-rc stop --all --host`) не должен провалиться в «выполнить здесь»: молчаливый
локальный запуск в этом случае погасил бы сессии не на той машине. argparse требует
значение у флага, и ошибка видна сразу, а не после того, как что-то уже погашено.

**Неинтерактивный ssh не читает `.zshrc`.** `ssh host cmd` (в отличие от `ssh -t host`)
не поднимает login shell и не подхватывает `~/.local/bin` — именно туда `uv tool
install` кладёт `claude-rc`. `proxy.remote_argv` подставляет этот каталог в `PATH` сам,
а не полагается на окружение удалённого шелла.

**Относительный путь под `--host` — отказ, а не догадка.** Команда на другой машине
выполняется как обычный локальный `claude-rc`, у которого нет понятия о каталоге,
откуда её позвали: `.` или `../repo` разрешились бы против чужого шелла и чужого
рабочего каталога. `proxy` отказывает на относительных путях вместо того, чтобы
угадать, что имелось в виду.

**Хвост панели в `<pre>` обрезан под лимит Telegram.** Сообщение длиннее 4096 символов
Telegram отклоняет целиком — обработчики `/mcp` и `Tail` режут текст перед отправкой
сами, а не полагаются на то, что панель всегда короткая.

**Шаг имени идёт через `offer_start`, а не в обход него.** Имя сессии — это
дополнительный шаг перед стартом, а не отдельный путь запуска; хендлер выбора каталога
по-прежнему зовёт `offer_start`, чтобы не потерять предложение Continue/резюме
диалога, которое там уже было до имени.

**`connect --start --branch` проверяет конфиг тем же гейтом, что и `start`.** Оба
зовут `_worktree_config_error()` перед созданием worktree — разведи эту проверку по
двум местам, и `connect` мог бы пропустить то, что `start` отклонил бы.

## Соглашения

- Ответы, комментарии и сообщения коммитов — русские; код, идентификаторы и логи —
  английские. Подписи кнопок в интерфейсе — английские.
- **README живёт в двух версиях.** `README.md` — английский (его видит GitHub, PyPI
  и человек со стороны), `README.ru.md` — русское зеркало. Меняешь поведение — правь
  обе; расхождение хуже отсутствия перевода. Раздел «Design notes» в английской
  версии — выжимка из «Грабли» ниже, при добавлении новых граблей дополняй и его.
- Коммиты атомарные, в стиле Conventional Commits. В теле объясняем **почему**, а не
  что: диффом видно и так.
- Комментарии в коде — только там, где решение неочевидно. Очевидное не комментируем.
- Изменение поведения сопровождается тестом. Тесты не отключаем, чтобы позеленить.
- `config.toml` содержит боевой токен и в git не попадает. В примерах правим только
  `config.example.toml`.

## Тесты

Быстрые и без сети. Два стиля:

- `test_remote.py` подменяет `remote._run` заглушкой — tmux не запускается. Плюс один
  сквозной тест на настоящем tmux с фейковым `claude` (для этого существует константа
  `CLAUDE_BIN`); без tmux он пропускается.
- `test_worktrees.py` работает на настоящих временных git-репозиториях: git быстрый,
  а мокать его пришлось бы так подробно, что тест перестал бы что-либо доказывать.

## Code Review Guidelines

Раздел читает автоматический ревьюер (`.github/workflows/claude-review.yml`) и человек.
Фокус — не стиль (его гейтит ruff), а то, что ломается тихо.

**Что искать, по убыванию важности:**

1. **Секреты и доступ.** Токен бота или содержимое `config.toml` в логах, коде или
   сообщениях. Ослабление проверки `allowed_user_id` или обработчик, который её не
   делает. Ссылка на сессию, утёкшая туда, где её видит не владелец.
2. **Небезопасный запуск.** Пользовательский ввод, попадающий в команду tmux, git или
   shell без `shlex.quote`. Путь из сообщения, подставленный в команду как есть.
3. **Потеря работы пользователя.** Удаление worktree в обход `blockers`, `force` по
   умолчанию, снос каталога с незакоммиченными изменениями, гашение сессии там, где
   этого не ждут.
4. **Регрессии контракта сессий.** Поиск сессии по имени вместо `realpath` каталога.
   Повторный запуск, плодящий вторую сессию в том же каталоге. Потеря `@rc_url`.
   Автоответ на диалог доверия вместо кнопки.
5. **Интеграционные грабли.** Неверный target-синтаксис tmux (`=имя` против `=имя:`).
   `callback_data` длиннее 64 байт. Работа с `query.message` без сужения до `Message`.
   Внешний вызов без таймаута.
6. **Молчаливые сбои.** Проглоченное исключение, ошибка tmux или git, не доехавшая до
   пользователя, `except` без объяснения почему.
7. **Отсутствие тестов** на изменение поведения.

**Чего не писать:** придирок к стилю и форматированию, спекуляций «а вдруг когда-нибудь»,
предложений крупного рефакторинга без выгоды для корректности или надёжности.

## Границы

Гейта прав на стороне бота нет и не планируется: RC-сессия интерактивная, разрешения
выдаются в приложении Claude. Единственная защита — `allowed_user_id`. Кто её прошёл,
получает на машине полноценный Claude Code со всеми токенами в `~`. Это осознанный
размен, а не недоделка — не «чини» его половинчатыми проверками в боте.
